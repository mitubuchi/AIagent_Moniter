# AgentWatch

AI エージェント（Claude Code / Claude Desktop / MCP サーバー）が**読み込むもの**と、
PC の**常駐・通信経路**を記録しておき、あとから変わったところを見つける。

読むだけで、設定もレジストリも書き換えない。管理者権限は要らない。書き込むのは `state\` だけ。

## できること・できないこと

エージェントは、設定ファイルに書かれたコマンドを確認なしに起動し、指示ファイルに書かれた文章に従う。
だから PC に入り込んだ側は、新しいマルウェアを置かなくても**設定を 1 行書き足すだけ**で、
エージェントの権限（ファイル・シェル・トークン）をそのまま使える。このツールが見るのはそこ。

| | |
|---|---|
| 見つけられる | 設定・指示・フックの書き換え、MCP サーバーの追加や差し替え、自動起動やタスクの追加、通信の行き先の変更 |
| 見つけられない | 記録した項目に触れない攻撃（メモリ上だけで動くもの、資格情報を読むだけのもの、カーネルに入ったもの） |
| 止められない | 何も止めない。**気づくための道具**で、防ぐ道具ではない |

**同じユーザーの権限で動くものは、このツールも基準も書き換えられる。** それを前提に 2 つ備えてある。

- `baseline` が出す**指紋**を PC の外（紙・スマホ）に控える。`check` の 1 行目と合わなければ、基準が差し替えられている
- `-StateDir` で基準を USB メモリーなどに置ける。スクリプト自身が変わったときも `check` が言う

## 使い方

```powershell
pwsh -File AgentWatch.ps1 baseline   # いまの状態を「確かめた状態」として記録する
pwsh -File AgentWatch.ps1 check      # 記録と比べ、変わったところを出す
pwsh -File AgentWatch.ps1 watch      # 5 分ごとに check を繰り返す（中以上の変化で音を鳴らす）
pwsh -File AgentWatch.ps1 status     # Claude の子プロセスと通信先を一覧する
```

⚠️ **`baseline` は Windows Terminal から取ること。** Claude Desktop（MSIX 版）の中から起動したプロセスは、
AppData やレジストリが振り替えられた景色を見ている。中で取った基準を外で `check` すると、
ずれが変化として出ることがある。

変化が出たら、**自分でやった覚えがあるか**を確かめる。覚えがあれば `baseline` を取り直す
（前の基準は `baseline.prev.json` に残る）。覚えがなければ、その項目を調べる。
検知の記録は `state\events.log` に 1 行 1 件の JSON で残る。

`check` の終了コード: `0` 変化なし（低だけを含む） / `1` 中以上の変化、取れなかった項目、スクリプト自身の変化 / `2` 基準が無い

| 引数 | |
|---|---|
| `-ProjectRoot C:\Claude,D:\Work` | プロジェクトの置き場所。直下の各フォルダーを見る（既定 `C:\Claude`） |
| `-StateDir E:\agentwatch` | 基準と記録の置き場所（既定 `state\`） |
| `-IntervalSec 300` | `watch` の間隔 |
| `-SkipSystem` | PC 側（レジストリ・タスク・サービス・通信経路）を見ない |

## 見ているもの

**エージェントが読み込むもの**

| 分類 | 対象 | 重さ |
|---|---|---|
| MCP サーバー | `~\.claude.json`（全体・プロジェクトごと）、`claude_desktop_config.json`、各プロジェクトの `.mcp.json`、Cursor / VS Code / Windsurf / Gemini の設定 | 高 |
| エージェントの設定 | `settings.json` / `settings.local.json` の `hooks` `env` `permissions` ほか全部の欄 | 高〜低 |
| 指示・スキル | `CLAUDE.md` と、そこから `@` で取り込まれるファイル、`skills` `commands` `agents` `hooks` `rules` `plugins` | 中 |
| 自動メモリ | `~\.claude\projects\*\memory\` | 低 |
| シェルの起動時に読むもの | PowerShell のプロファイル、`.bashrc` など、`.ssh\config`、`.npmrc` | 高・中 |
| git | フック（`.sample` 以外）、設定のうちコマンドを実行させられる欄（`fsmonitor` `sshCommand` `hooksPath` など） | 高・中 |
| 資格情報 | `.credentials.json`、SSH の秘密鍵、`gh` のトークン — **中身は読まず、誰が読めるかだけ** | 高 |
| Claude Code 本体 | 署名が有効で、署名者が変わっていないこと | 高 |

**PC の常駐と通信経路**

| 分類 | 対象 | 重さ |
|---|---|---|
| 自動起動 | `Run` / `RunOnce`、`Winlogon`、`cmd.exe` の `AutoRun`、スタートアップ | 高・中 |
| タスク・サービス | 全部（実行するものと、無効かどうか） | 中 |
| 待ち受け | どのプログラムが、ほかの機械から届く形で待ち受けているか | 中・低 |
| 通信の行き先 | プロキシ、`hosts`、信頼されたルート証明書、`ANTHROPIC_BASE_URL` `HTTPS_PROXY` `NODE_OPTIONS` などの環境変数、`Path` | 高・中 |

基準に残すのは**ハッシュと名前だけ**。環境変数やヘッダーの値（トークン）は残さない。
ただし MCP サーバーの**引数**と、許可リストの中身はそのまま入る。`state\` を人に渡さないこと。

基準とは別に、いまの設定のうち形の怪しいもの（エンコードされた PowerShell、ダウンロードしてそのまま実行、
何でも通す許可、版を固定しない `npx` など）を毎回挙げる。**当たったから悪性、外れたから安全、ではない。**

## 確かめたこと・確かめていないこと

2026-11-10、偽のホームフォルダーに 19 か所の書き換えを入れ、全部を拾うことを実測した
（`~\.claude.json` の使用回数のような無関係な変化は拾わない）。実機では 676 項目・約 6 秒。

- 続けて取った基準のあいだで、BITS サービスが手動⇄自動を勝手に行き来した。サービスは「無効かどうか」までを比べるようにした
- **数日にわたる誤検知の量は測っていない。** Windows Update のあとは、タスクやサービスがまとまって出るはず
- `watch` の音と、`status` の「署名なし」の表示は、実際に鳴る・出るところまでは見ていない

## 併せてやること

このツールは気づくところまで。入り込まれにくくするのは別の話で、効くのは次のあたり。

- エージェントの許可を広げすぎない（`Bash(*)` や `bypassPermissions` を常用しない）
- MCP サーバーは版を固定する（`npx -y pkg@1.2.3`）。配布元が乗っ取られた版を、起動のたびに取りにいかない
- 知らないリポジトリを開くときは、`.mcp.json` と `.claude\` を先に読む
- ふだん使いのアカウントを管理者にしない。入り込まれても、PC 全体までは届かない
